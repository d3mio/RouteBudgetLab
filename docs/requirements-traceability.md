## 2. Research Questions (RQ1–RQ3) and Hypotheses

| RQ ID | Research Question | Target Experiment | Status | Notes / Hypotheses |
|---|---|---|---|---|
| **RQ1** | Can a low-level MAPF-LNS repair search be suspended at an arbitrary cutoff and resumed under unchanged external constraints to produce valid, collision-free solutions consistent with uninterrupted execution, and what memory and latency overheads are incurred? | E1 (WP2 / Phase 3) | **RESEARCH QUESTION (Evaluated within E1 Scope)** | Evaluated across 10 deterministic test categories in `tests/e1_resumption_tests.cpp` on `random-32-32-20` (10 agents, Space-Time $A^*$). Collision-free valid paths verified by independent validator. Save/restore latency measured at $3.92\ \mu$s Release / $15.62\ \mu$s ASan; memory 1024 bytes (1 KB). Exact cell-by-cell path equality demonstrated for uninterrupted vs resumed execution under identical expansion limits. Unfinished frontier discarded in macro-prefix mode; repeated work recorded. Broader multi-map evaluation completed in Phase 7. |
| **RQ2** | What fraction of saved repair checkpoints remain compatible with evolving external agent reservations across subsequent LNS iterations, and does conservative constraint validation prevent invalid solution commits compared with unvalidated reuse? | E4 (WP3 / Phase 4) | **RESEARCH QUESTION (Evaluated within E4 Scope)** | Evaluated across 8 test categories and 20 controlled scenarios in `tests/e4_compatibility_tests.cpp`. Two-stage validation achieves sub-microsecond latency ($0.24 - 0.71\ \mu$s) and retains 75% more checkpoints under external perturbations (14 vs 8) than discard-on-change, while detecting all simulated vertex conflicts, edge swaps, stay-at-goal occupancies, and neighborhood mutations. 0 invalid solution commits verified across all evaluated policies in both Release and ASan/UBSan builds. In Phase 7 benchmark execution, selective compatibility tied discard-on-change in 86 of 96 conditions due to plateauing repair yield. |
| **RQ3** | Does an overhead-aware resume-or-start heuristic controller informed by lightweight search-progress features achieve lower deadline solution cost (Sum of Costs / Total Delay) than restart-only LNS, fixed round-robin resumption, and published adaptive baselines within identical wall-clock deadlines? | E2, E3, E5, E6 (WP5 / Phase 7) | **EVALUATED & QUALIFIED (Phase 7)** | Evaluated across full 768 sequential reference runs under Protocol A (refinement-only) and Protocol B (end-to-end) across $N=96$ paired conditions. Under Protocol A, FIFO resumption achieved a positive average improvement (+13.36 points) in the evaluated sample, concentrated heavily on `ost003d` (+71.46 points; negative mean -6.00 when `ost003d` omitted; clustered bootstrap 95% CI spans zero: [-9.30, +52.15]). Adaptive slicing and feature-based scoring yielded inconclusive differences (-16.97 and -2.49 points). Under Protocol B, published BALANCE achieved lower final costs (-232.65 points) through uninstrumented monolithic search, but overran deadlines on 79.2% of runs (up to 5.65 ms) compared to 0.00 $\mu$s for RBL (100.0% compliance within $\le 1.0\ \mu$s tolerance). |

## 5. Discrepancies Between Proposal and Actual Repository / Environment

1. **Backbone Implementation Language Standard:**
   - *Proposal:* Proposed C++17 backbone.
   - *Actual Repository:* Upstream `thomyphan/anytime-mapf` (BALANCE) was written in C++14 and uses `std::random_shuffle` (deprecated in C++14, removed in C++17).
   - *Reconciliation:* Upstream baseline preserved as C++14 reference (`scripts/build_baseline.sh release`). A compliant C++17 build was verified using `-D_LIBCPP_ENABLE_CXX17_REMOVED_RANDOM_SHUFFLE` on macOS libc++ and `-DRBL_CXX_STANDARD=17` via deferred CMake target property override. RouteBudget Lab's own code (`rbl_validate`, etc.) compiles strictly under C++17 (`set(CMAKE_CXX_STANDARD 17)`).

2. **Output Path Coordinate Convention:**
   - *Proposal / Intuition:* Nathan Sturtevant's Moving AI benchmark standard uses `(column, row)` = `(x, y)`.
   - *Actual Solver Output:* In `LNS::writePathsToFile` (line 909), the solver outputs `(instance.getRowCoordinate(loc), instance.getColCoordinate(loc))` which is `(row, col)` = `(y, x)`!
   - *Reconciliation:* The independent validator (`rbl_validator.hpp` and `rbl_validate`) defaults to `(row, col)` for solver-generated path files and supports `--coords xy` for standard coordinate fixtures. Verified against actual baseline paths `paths1.txt` and regression tests.

3. **Baseline `--maxIterations` Default Traps:**
   - *Proposal / Upstream README:* Upstream README gives `./balance ...` without `--maxIterations`.
   - *Actual Behaviour:* Upstream `driver.cpp` defaults `--maxIterations` to `0`, which causes the outer LNS loop to exit immediately after 1 iteration (after 0.005 s).
   - *Reconciliation:* Documented in `docs/decisions.md`. All benchmark/baseline scripts explicitly pass `--maxIterations=1000000`.

4. **macOS Apple Silicon & Toolchain Environment:**
   - *Environment:* Apple M3 arm64, macOS 26.3, Command Line Tools 17.0.0.
   - *Actual Constraint:* Xcode license was not agreed by the system user, causing `/usr/bin/g++`, `/usr/bin/clang++`, `/usr/bin/git`, and `/opt/homebrew/bin/brew` shims to fail with an interactive license error.
   - *Reconciliation:* Non-privileged fallback implemented in `scripts/common.sh`: directly calls `/Library/Developer/CommandLineTools/usr/bin/clang++` with `SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk`. No `sudo` or unauthorized license acceptance was executed.
