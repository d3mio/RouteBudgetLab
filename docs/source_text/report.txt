1. Executive Abstract and Domain Motivation

1.1 Executive Abstract
As of 19 October 2026, I am finalising the literature review, candidate research gap, technical design and evaluation
methodology. Implementation is the next phase and has not yet started. The architecture, controller formulation
and experimental procedures presented here are proposed designs. No prototype performance measurements or
experimental results are claimed in this submission. Anytime Multi-Agent Path Finding (MAPF) planners based on
Large Neighbourhood Search (MAPF-LNS) iteratively improve an initial collision-free route plan by repeatedly
destroying and replanning subsets of agent trajectories within a fixed wall-clock computation deadline. In congested
grid environments such as automated fulfilment warehouses, individual repair searches frequently consume
substantial computation and are interrupted by per-iteration time cutoffs before finding an improving path set.
Existing anytime MAPF controllers reviewed in this study discard internal search progress upon interruption, losing
expanded search nodes and already-routed sub-neighbourhood trajectories. However, naively saving and resuming
an interrupted repair search across later LNS iterations is unsafe: if intervening accepted repairs modify the
trajectories of external agents outside the saved neighbourhood, the dynamic space-time reservation table changes,
which can invalidate the saved search state and introduce vertex or edge-swap collisions.
In this project, I propose to investigate, design, implement, and empirically evaluate RouteBudget Lab, a standalone
software engineering research artefact centred on a constraint-validated repair-resumption mechanism for
deadline-aware anytime MAPF. The proposed architecture comprises four core components to be integrated into an
established C++17 MAPF-LNS backbone: (1) a proposed Resumable Repair Engine designed to suspend, checkpoint,
and restore a low-level Prioritized Planning / Safe Interval Path Planning (SIPP) repair solver within a bounded in-
memory store (maximum K = 2 checkpoints); (2) a proposed Conservative Constraint Validator designed to test
compatibility between a saved checkpoint's external spatio-temporal reservation footprint and the current
incumbent plan, discarding any checkpoint whose compatibility cannot be conservatively verified; (3) a proposed
Lightweight Remaining-Work Estimator that extracts internal search-progress features (expanded node count, open-
list frontier size, sequential prefix progress, and heuristic delay gap) to predict expected accepted cost improvement
and remaining active search time; and (4) a proposed Overhead-Aware Resume-or-Start Controller heuristic that
arbitrates between resuming a validated checkpoint and initiating a fresh repair neighbourhood under the
remaining wall-clock deadline while accounting for validation, restoration, initialisation, estimation, controller, and
conditional checkpoint-saving overheads.
Following Design Science Research (DSR) coupled with quantitative empirical algorithmics on public Moving AI
MAPF benchmarks (50–100 agents across warehouse, random, maze, room, and city topologies), I plan to execute
six controlled experiments (E1–E6) testing pause/resume equivalence, restart-only versus checkpoint-enabled
repair, fixed round-robin versus adaptive resume-or-start control, conservative validation versus unconditional
discard, progress-feature ablations, and end-to-end comparisons against published adaptive baselines (BALANCE,
ADDRESS, TACKLE, and delay-based heuristics). Technical uncertainties regarding low-level C++ state-cloning
overhead and constraint invalidation rates will be managed through a planned Gate 1 feasibility check at the
completion of Work Package 1 (WP1, Mid November 2026) and a proposed macro-prefix checkpointing fallback.

1.2 Domain Context and Industrial Significance
Multi-Agent Path Finding (MAPF) is a core coordination problem in artificial intelligence, robotics, and real-time
software systems engineering, requiring the computation of collision-free discrete-time trajectories for multiple
autonomous agents navigating a shared graph from assigned start vertices to goal vertices (Stern et al., 2019; Li et
al., 2021). In high-density industrial deployments—such as automated guided vehicle (AGV) fleets in e-commerce
fulfilment centres, airport surface movement control, and multi-robot manufacturing cells—route planners operate
under strict real-time dispatch deadlines (typically 1 to 30 seconds). Because computing optimal collision-free
trajectories minimizing Sum of Costs or Total Delay is NP-hard (Yu and LaValle, 2013), optimal solvers such as
Conflict-Based Search (CBS) rarely scale to 50–100+ agents within tight operational cutoffs.

Consequently, practical systems rely on anytime MAPF-LNS planners (Li et al., 2021; Phan et al., 2024, 2025, 2026;

3.2 Thematic Synthesis of Prior Art

Theme 1: Adaptive Neighbourhood and Seed Selection in Anytime MAPF-LNS
The foundational MAPF-LNS framework (Li et al., 2021) introduced an anytime loop combining three handwritten
destroy heuristics (random, agent-based delay, and map-based intersection) selected via a roulette-wheel weight
update. Subsequent AAAI papers by Phan et al. progressively refined how candidate repairs are chosen before each
repair execution:
•      BALANCE (Phan et al., 2024, AAAI): Replaces roulette-wheel selection with a two-level multi-armed bandit
       (Thompson Sampling for destroy-heuristic choice coupled with alpha-decaying Gaussian bandits for
       neighbourhood size N). BALANCE demonstrates that online adaptation of destroy heuristic and neighbourhood
       size is established prior art.
•      ADDRESS (Phan et al., 2025, AAAI): Identifies that selecting which specific delayed 'seed' agent anchors the
       neighbourhood is critical, restricting Thompson Sampling to a dynamic top-K candidate set of maximally
       delayed agents to avoid large neural overhead.
•      TACKLE (Phan et al., 2026, AAAI): Combines heuristic delay preference with truncated counterfactual learning
       over the top-K seed pool and resets bandit parameters when the candidate pool shifts. Importantly, 'truncated'

       in TACKLE refers to candidate-pool restriction, not interrupting and resuming an in-progress low-level repair
       search.
•      Reevaluation of LNS for MAPF (Tan et al., 2025, SoCS): Conducts a rigorous empirical re-evaluation of MAPF-
       LNS across standardized C++ implementations, demonstrating that well-tuned rule-based delay heuristics
       remain highly competitive with learning-based selectors when wall-clock controller overhead is fairly counted.
       This directly motivates our requirement to measure all save, restore, validation, and decision overheads inside
       the wall-clock deadline.
Critical Synthesis of Theme 1: Where the papers agree is that focusing LNS effort on high-delay agents significantly
accelerates anytime convergence. Where they share a common structural limitation is that MAPF-LNS, BALANCE,
ADDRESS, and TACKLE all treat every repair execution as an atomic, start-from-scratch black-box call. Whenever a
repair is interrupted by a per-iteration time cutoff, its internal search frontier and any partially routed sub-
neighbourhood paths are discarded completely.

Theme 2: Search-Information Reuse and Constraint-Aware Caching in MAPF
A second literature stream investigates reusing search effort across planning episodes in MAPF:
•      X* (Vedder and Biswas, 2021, Artificial Intelligence): Embeds optimal MAPF solvers within a Windowed
       Anytime Multiagent Planning Framework (WAMPF) for sparse domains. When local repair windows expand
       over time, X* applies an A* search-tree transformation to reuse previously expanded nodes and heuristic
       evaluations across growing spatial-temporal windows.
•      CAHC — Conflict-Aware Heuristic Caching (To, Nguyen and Pham, 2025, arXiv:2512.12243): Addresses the
       limitation that traditional heuristic caches fail when high-level conflict constraints alter the reachable state
       space. CAHC introduces a compact conflict fingerprint encoding active constraints and a spatial-temporal-
       geometric relevance filter to cache and retrieve conflict-dependent heuristic values in constraint-based MAPF
       (evaluated in a CAR-CHASE case study on 480 car-like robot CL-CBS benchmark instances, with the general
       architecture positioned for CBS and MAPF-LNS).
Critical Synthesis of Theme 2: X* and CAHC demonstrate that reusing search information across changing constraint
contexts is theoretically viable and computationally beneficial. However, X* is engineered for expanding spatial
windows in joint-state A* rather than sequential prioritized LNS repairs. Conversely, CAHC caches scalar heuristic
distance estimates indexed by conflict fingerprints, but still restarts the low-level repair search from the initial state.
Neither method suspends an active LNS repair execution state (open/closed lists and completed sequential agent
prefixes), validates its spatio-temporal reservation footprint against external LNS plan mutations, or schedules
resumption against fresh candidate neighbourhoods.

Theme 3: Runtime Prediction and Computational Scheduling Under Deadlines
Outside MAPF-LNS, algorithm selection and scheduling under timeouts have been studied extensively:
•      Algorithm Selection for Optimal MAPF (Kaduri, Boyarski and Stern, 2020, ICAPS): Demonstrated supervised
       machine learning for selecting among optimal MAPF solvers on static instances.
•      Run2Survive (Tornede et al., 2020, ACML): Introduced survival analysis to model right-censored solver
       runtimes (runs terminated by timeouts) for decision-theoretic algorithm selection.
•      RunAndSchedule2Survive (Margraf et al., 2025, ACM TELO): Combined survival-based runtime models with
       evolutionary optimization to compute static or dynamic solver schedules under time budgets.
Critical Synthesis of Theme 3: Classical algorithm scheduling assumes that pausing and later resuming a solver
operates on a static problem instance whose external constraints never mutate while the solver is suspended. In
anytime MAPF-LNS, every accepted repair mutates the shared incumbent plan P_inc, creating a dynamic state-
invalidation coupling between accepted repairs and suspended checkpoints that generic algorithm schedulers cannot
handle without domain-specific constraint validation.

4. Research Problem and Gap Analysis

4.1 Classical One-Shot MAPF Formulation
In classical one-shot Multi-Agent Path Finding (Stern et al., 2019), we are given an unweighted, four-connected
undirected grid graph G = (V, E) and a set of m agents A = {a_1, a_2, ..., a_m}. Each agent a_i has a distinct start
vertex s_i in V and a distinct goal vertex g_i in V. Time is discretised into integer steps t = 0, 1, 2, .... At each step t,
an agent located at vertex p_i(t) in V can either move to an adjacent vertex p_i(t+1) in V such that (p_i(t), p_i(t+1))
in E, or wait in place such that p_i(t+1) = p_i(t). Under the standard stay-at-goal convention (Stern et al., 2019; Li et
al., 2021), an agent reaching its goal g_i at arrival time T_i remains at g_i for all subsequent steps t >= T_i, continuing
to occupy that vertex.
A joint route plan P = {p_1, p_2, ..., p_m} is collision-free (valid) if and only if for all distinct agent pairs (a_i, a_j) with
i != j and all time steps t >= 0:
•      Vertex Conflict Constraint: p_i(t) != p_j(t) (no two agents occupy the same vertex at the same time step); and
•      Edge Swap Conflict Constraint: not (p_i(t) = p_j(t+1) and p_i(t+1) = p_j(t)) (no two agents traverse the same
       undirected edge in opposite directions simultaneously).
The standard objective in anytime MAPF is to minimise the Sum of Costs (SoC), denoted C(P), or equivalently the
Total Delay D(P) relative to individual shortest-path distances LB_i = dist_G(s_i, g_i):



    Anytime MAPF Cost and Delay Objectives
    C(P) = sum_{i=1..m} T_i
    LB = sum_{i=1..m} dist_G(s_i, g_i)
    D(P) = C(P) - LB = sum_{i=1..m} (T_i - dist_G(s_i, g_i))




4.2 Anytime Large Neighbourhood Search (MAPF-LNS)
Because finding an optimal collision-free plan P* minimizing C(P) is NP-hard (Yu and LaValle, 2013), Anytime MAPF-
LNS (Li et al., 2021) decouples initial feasibility from iterative cost refinement. First, an initial solver (such as
Prioritized Planning with Safe Interval Path Planning, PP+SIPP, or EECBS) computes an initial collision-free incumbent
plan P_inc. Thereafter, while wall-clock time remains before the global deadline B, the planner executes a destroy-
and-repair loop:
•      1. Destroy Step: A destroy heuristic selects a subset (neighbourhood) of Nk agents A_k subset A (typically |A_k|
       in {4, 8, 16, 32}) whose current trajectories exhibit high delay or path congestion.
•      2. External Constraint Freezing: The trajectories of all external agents A \ A_k are held fixed in a spatio-
       temporal Reservation Table (or Conflict Avoidance Table, CAT), representing dynamic obstacles.
•      3. Repair Step: A low-level repair solver (typically sequential Prioritized Planning with SIPP or space-time A*
       over a specified ordering of A_k) searches for new collision-free paths P'_{A_k} that avoid all external
       reservations in A \ A_k and reduce the neighbourhood cost sum_{i in A_k} T_i.
•      4. Acceptance Check: If the repair completes within its allocated per-iteration time slice and achieves C(P') <
       C(P_inc), P_inc is updated to P'; otherwise, the candidate repair is discarded and P_inc is retained.

4.3 The Computational Problem: Interrupted Repairs vs. Evolving Constraints
In deadline-aware anytime MAPF, each repair attempt operates under a local time slice or global deadline
constraint so that a single hard subproblem does not monopolise the entire planning budget (Li et al., 2021; Tan et
al., 2025). When a repair search on neighbourhood A_c is interrupted before completion, standard MAPF-LNS
implementations discard the entire partial search state—including expanded space-time A* or SIPP nodes, open
priority queues, closed sets, and already-replanned prefix agents within the sequential priority ordering of A_c.

Discarding interrupted repairs wastes computation when the search was close to resolving a local bottleneck.
However, preserving and later resuming a suspended repair checkpoint C_i introduces a fundamental correctness
and scheduling dilemma:
•      1. External Constraint Invalidation Hazard: Between the time checkpoint C_i is suspended at iteration k1 and
       considered for resumption at a later iteration k2 > k1, other accepted repairs may have modified the
       trajectories of external agents in A \ A_c. Because the search nodes stored inside C_i were expanded under the
       reservation table of iteration k1, resuming C_i without verifying whether the modified external paths intersect
       C_i's spatial-temporal search space can produce invalid, colliding routes or corrupted heuristic bounds.
•      2. Opportunity Cost and Overhead Trade-off: Even if a saved checkpoint C_i remains compatible with current
       external constraints, resuming it is not guaranteed to be optimal: serialising, restoring, and validating C_i incurs
       wall-clock and memory overhead, and a newly generated repair neighbourhood N_j might yield a larger
       expected cost reduction per unit of remaining time than continuing C_i.

    FORMAL PROBLEM STATEMENT (CURRENT SITUATION -> LIMITATION -> CONSEQUENCE -> NEED)
    Current Situation: Anytime Multi-Agent Path Finding planners (such as MAPF-LNS and its adaptive variants BALANCE,
    ADDRESS, and TACKLE) iteratively improve collision-free plans by executing time-bounded destroy-and-repair
    searches over selected agent neighbourhoods.

    Limitation / Challenge: When a repair search is interrupted by a per-iteration cutoff or budget allocation decision,
    existing MAPF-LNS controllers discard the ongoing search state entirely. Conversely, naively checkpointing and
    resuming an interrupted repair across iterations is unsafe because intermediate accepted repairs alter external
    agents' paths and spatio-temporal reservation tables, potentially invalidating saved search states.

    Consequence: Planners either suffer wasted search computation from repeated scratch restarts on complex
    bottlenecks, or risk collision-safety violations and net wall-clock slowdowns if search states are reused without formal
    constraint verification and remaining-work valuation.

    Need for Investigation: There is a need to investigate a constraint-validated repair-resumption mechanism and
    resume-or-start controller that (i) safely checkpoints and restores interrupted repair searches, (ii) conservatively
    validates saved states against evolving planning constraints, and (iii) determines whether resuming an eligible
    checkpoint yields higher expected net improvement within a global deadline than starting a fresh repair.




4.4 Candidate Research Gap Analysis and Proposed Contribution

    CANDIDATE RESEARCH GAP & PROPOSED CONTRIBUTION STATEMENT
    Within the 2019–2026 literature reviewed in Section 3, established research provides adaptive neighbourhood and
    seed-agent selection for MAPF-LNS (BALANCE, ADDRESS, TACKLE), search-tree transformation across expanding
    spatial windows (X*), conflict-fingerprinted heuristic value caching (CAHC), and survival-based algorithm scheduling
    on static problem instances (Run2Survive, RunAndSchedule2Survive). However, the reviewed studies do not present
    an integrated mechanism within anytime MAPF-LNS that (1) suspends and checkpoints interrupted sequential repair
    searches, (2) conservatively validates whether saved search states remain conflict-compatible after external agent
    trajectories change in the incumbent plan, and (3) arbitrates between resuming a validated checkpoint and starting a
    fresh repair using internal search-progress features and explicit wall-clock overhead accounting under a global
    planning deadline. Addressing this candidate research gap is the proposed contribution of RouteBudget Lab and is
    framed as a falsifiable empirical hypothesis to be tested during implementation.

5.3 Technical Investigation of Low-Level Solver Checkpointing Granularities
In MAPF-LNS, a repair attempt replans a destroyed neighbourhood A_c = (a_(1), ..., a_(N)) sequentially using
Prioritized Planning with Safe Interval Path Planning (SIPP) or Space-Time A*. When interrupted at active search
slice cutoff Delta, two candidate checkpointing granularities are identified for investigation in WP1: (a) micro-level
search-frontier checkpointing, which saves both the r_done < N already-replanned prefix trajectories P'_{1..r_done}
and the active open/closed search structures (Open_{r+1}, Closed_{r+1}) of the currently expanding agent
a_(r_done+1); and (b) macro-level prefix checkpointing (Fallback 1A), which saves only the completed sequential
prefix trajectories P'_{1..r_done} and resumes from agent a_(r_done+1). Both granularities are captured by the
proposed in-memory checkpoint tuple C_i:

    Proposed In-Memory C++ Checkpoint State Tuple Specification (Table 5.3)
    C_i = (id_i, A_c, ord(A_c), r_done, P'_{1..r_done}, Open_{r+1}, Closed_{r+1}, sig_ext(A \ A_c), u_spent, c_base,
    rng_state)
    Note: Under Macro-Prefix Checkpointing (Fallback 1A), Open_{r+1} and Closed_{r+1} are empty, and resumption
    restarts agent r_done + 1 while preserving P'_{1..r_done}.

Here sig_ext(A \ A_c) records the external constraint context (per-agent trajectory version counters and spatio-
temporal reservation footprint R(C_i)) against which C_i was expanded or last validated, u_spent is the cumulative
active search time already expended on C_i in prior slices, and c_base is the pre-repair cost of A_c. During Work
Package 1 (WP1, Late Oct – Mid Nov 2026), planned profiling experiments will measure the empirical memory and
latency cost of micro-level frontier cloning versus macro-level prefix checkpointing.

7.2 Proposed Technical Specification of the Four Core Research Components

Component 1: Proposed Resumable Repair Engine (Bounded Store K <= 2)
Building on the checkpoint state tuple C_i defined in Section 5.3 (Table 5.3), the proposed Resumable Repair Engine
instruments the low-level Prioritized Planning + SIPP / Space-Time A* solver to check a cooperative interruption
condition at each node expansion or agent-level step against the allocated active repair-search slice Delta. Every
repair or resumption executes on an isolated working copy so that an interruption never leaves the incumbent plan
P_inc partially modified. When interrupted at active search time Delta, if the search meets a minimum progress
threshold, its state tuple C_i is saved into the bounded in-memory checkpoint store S_chk (capacity K <= 2, evicting
the lowest-scored entry when full), and the actual elapsed checkpoint-saving time t_save is charged immediately to
the global wall-clock deadline B.

Component 2: Proposed Conservative Constraint Validator & Safeguard Separation
Suppose checkpoint C_i was saved at iteration k_1 and is reconsidered at a later iteration k_2 > k_1 under the
current incumbent plan P_inc^(k_2). Let A_mod subset (A \ A_c) denote the subset of external agents whose
trajectories in P_inc^(k_2) have changed since C_i was saved or last validated. Crucially, post-repair final-path
collision checking (the proposed Independent Path Validator, FR-06) only inspects a completed candidate plan
P_cand before commit; final-path collision checking alone does not prove that a resumed checkpoint's internal
search state (its open/closed lists, safe intervals, g-values, and pruning decisions) remained valid under mutated
external reservations. Therefore, Component 2 is proposed as a pre-resumption safeguard that executes a two-
stage compatibility check (requiring soundness justification and empirical testing in Experiment E4):
•      Stage 1 — Trajectory Version Screen: Each agent a in A maintains a monotonic version counter v_traj[a]
       incremented whenever an accepted repair modifies its path in P_inc. If v_traj[e] matches C_i's recorded version
       for all external agents e in A \ A_c (A_mod is empty), C_i's external reservation table is unchanged and C_i is
       marked VALID in O(|A|) time.
•      Stage 2 — Conservative Spatio-Temporal Footprint Check: If A_mod is non-empty, the validator tests whether
       any modified external agent's old trajectory p_e^(k_1) or new trajectory p_e^(k_2) intersects the recorded
       spatio-temporal reservation footprint R(C_i) covering C_i's routed prefix paths P'_{1..r_done} and explored
       search states. Under the proposed conservative policy, if any reservation in R(C_i) was added, removed, or
       altered such that internal search-state consistency or prefix collision-freedom cannot be verified without re-
       expanding nodes, the validator marks C_i INVALID and evicts it from S_chk. While conservative screening may
       incur false rejections (discarding a checkpoint that might still have led to a valid path), it is designed to prevent
       resuming corrupted search states, complemented by the Independent Path Validator (FR-06) as a final post-
       repair check before any completed plan updates P_inc.

Component 3: Proposed Lightweight Remaining-Work Estimator
For each validated checkpoint C_i in C_valid(k) and each candidate fresh repair neighbourhood N_j in {N_1, ...,
N_M}, the proposed estimator extracts a compact feature vector phi(a) (comprising neighbourhood size |A_c|,
completed prefix ratio r_done / |A_c|, cumulative expanded nodes N_exp, open-list frontier size |Open|, current
heuristic delay gap of remaining agents in A_c, cumulative active search time already spent u_spent, local
congestion density, and remaining budget ratio b_k / B; for a fresh repair N_j, r_done = N_exp = |Open| = u_spent =
0). Given a candidate active repair-search slice Delta, a lightweight linear/ridge or calibrated tabular model (to be fit
offline on the training map partition during WP4; no fitted estimator or measured coefficients exist at this stage)

predicts two quantities: (i) E_hat[AcceptedImprovement(a, Delta)], the expected reduction in incumbent Sum of
Costs max(0, C(P_inc) - C(P_cand)) accepted within active search time Delta, where AcceptedImprovement(a, Delta)
is defined as zero whenever no valid improving repair is completed and accepted within Delta; and (ii)
E_hat[min(T_rem(a), Delta)], the expected active low-level search time expended during slice Delta, where T_rem(a)
denotes the remaining active repair-search time required for action a to reach completion (excluding action
overhead).

Component 4: Proposed Overhead-Aware Resume-or-Start Controller Heuristic
At iteration k, let B denote the global wall-clock deadline, t_now the elapsed monotonic wall-clock time, b_k = B -
t_now the remaining global wall-clock budget, and t_reserve > 0 a safety buffer reserved to finalise incumbent
commitment before B expires. In Step A of each iteration, stored checkpoints in S_chk are screened by Component
2 (incurring actual validation time t_val), and in Step B the fresh candidate pool {N_1, ..., N_M} is generated
(incurring t_pool), features are evaluated (incurring t_est), and candidate actions a in A_elig(k) = C_valid(k) union
{N_1, ..., N_M} are scored across a discrete slice grid D_grid (incurring t_ctrl). Because t_val, t_pool, t_est, and t_ctrl
are executed once during this pre-decision sweep, their actual elapsed time immediately advances t_now and
reduces b_k; to avoid charging already-incurred or shared sweep costs a second time, they are not re-added inside
the per-action prospective overhead term Overhead_hat(a). (If lazy validation were used instead of Step A
screening, estimated validation cost t_hat_val(C_i) would be included once inside Overhead_hat(C_i).) For any
candidate pair (a, Delta) where Delta is the maximum active repair-search time (excluding action overhead), the
provisional controller heuristic requires budget admissibility and evaluates expected accepted improvement per
unit of expected total action time:

  Proposed Overhead-Aware Controller Decision Heuristic (Provisional Design)
  Score(a, Delta) = E_hat[ AcceptedImprovement(a, Delta) ] / ( E_hat[ min(T_rem(a), Delta) ] + Overhead_hat(a) )

  Budget Admissibility Constraint:
   Delta + Overhead_hat(a) + t_reserve <= b_k        (where b_k = B - t_now is the remaining global wall-clock budget)

  Symbol Definitions & One-Time Overhead Accounting:
   • a in A_elig(k) = C_valid(k) union {N_1, ..., N_M}: Candidate action (resuming validated checkpoint C_i or starting
  fresh repair N_j).
   • Delta > 0: Maximum active low-level repair-search time allocated to action a, excluding explicitly accounted action
  overhead.
   • T_rem(a) >= 0: Remaining active low-level repair-search time required for action a to complete (excluding action
  overhead).
   • AcceptedImprovement(a, Delta): Accepted reduction in Sum of Costs max(0, C(P_inc) - C(P_cand)) if action a
  completes within active
     search time Delta and passes independent collision validation; defined as 0 whenever no valid improving repair is
  accepted within Delta.
   • Overhead_hat(a): Estimated additional action-specific overhead incurred upon executing action a, counted strictly
  once:
      Overhead_hat(C_i) = t_hat_restore(C_i) + t_hat_save_cond(C_i, Delta) [state restoration + conditional
  checkpoint save if interrupted]
      Overhead_hat(N_j) = t_hat_init(N_j) + t_hat_save_cond(N_j, Delta) [neighbourhood/solver init + conditional
  checkpoint save]
     (Pre-decision sweep costs t_val, t_pool, t_est, t_ctrl are already deducted from b_k = B - t_now and are not double-
  counted here.)



The controller selects (a*, Delta*) = argmax_{(a, Delta)} Score(a, Delta) over all admissible pairs satisfying Delta +
Overhead_hat(a) + t_reserve <= b_k (with a planned end-game ablation comparing Score(a, Delta) against direct
expected improvement when b_k allows only one final attempt). Crucially, Score(a, Delta) is a proposed heuristic
policy to be implemented and empirically evaluated in Experiments E3 and E5, not a proven optimal policy. During

initialisation (t_init), active repair search, independent path validation (t_verify), and conditional checkpoint saving

  Algorithm 1: Proposed Constraint-Validated Resume-or-Start Anytime MAPF Controller
  Input: Grid G=(V,E), starts/goals {(s_i,g_i)}, global wall-clock deadline B, reserve buffer t_reserve, max checkpoints
  K=2, slice grid D_grid
  Output: Validated collision-free incumbent plan P_inc, telemetry log L

  1: Start monotonic wall-clock timer t_now; initialise empty checkpoint store S_chk (capacity K=2)
  2: P_inc <- InitialMAPFPlanner(G, {(s_i,g_i)}, budget = B - t_reserve)
  3: if P_inc is None or not IndependentPathValidator(P_inc) then return NO_VALID_SOLUTION
  4: Initialise trajectory version vector v_traj[1..m] <- 0
  5: while (B - t_now) > t_reserve do
  6: // Step A: Pre-Decision Conservative Constraint Validation (actual t_val charged to t_now)
  7: for each saved checkpoint C_i in S_chk do
  8:      status, t_val <- ConservativeConstraintValidator(C_i, P_inc, v_traj)
  9:      if status == INVALID then Evict(S_chk, C_i); LogInvalidation(L, C_i, t_val)
  10: C_valid(k) <- S_chk
  11: // Step B: Candidate Pool & Heuristic Scoring (actual t_pool, t_est, t_ctrl charged to t_now)
  12: Pool_fresh <- GenerateCandidateNeighbourhoods(P_inc, M)
  13: A_elig(k) <- C_valid(k) union Pool_fresh; b_k <- B - t_now
  14: for each action a in A_elig(k) and active search slice Delta in D_grid do
  15:      Compute Overhead_hat(a) (= t_hat_restore + t_hat_save_cond for C_i; t_hat_init + t_hat_save_cond for N_j)
  16:      if Delta + Overhead_hat(a) + t_reserve <= b_k then
  17:         Score(a, Delta) <- E_hat[AcceptedImprovement(a, Delta)] / (E_hat[min(T_rem(a), Delta)] +
  Overhead_hat(a))
  18: if no admissible (a, Delta) exists then break
  19: Select (a*, Delta*) <- argmax_{(a, Delta)} Score(a, Delta)
  20: // Step C: Execute Resumption or Fresh Repair on Isolated Working Copy (max active search time Delta*)
  21: if a* is a validated checkpoint C_i in C_valid(k) then
  22:      RestoreState(C_i) [incurs t_restore]; outcome, P_cand, C_new <- ContinueRepair(C_i, min(Delta*, B - t_now -
  t_reserve))
  23: else
  24:      InitialiseRepair(a*) [incurs t_init]; outcome, P_cand, C_new <- StartFreshRepair(P_inc, a*, min(Delta*, B -
  t_now - t_reserve))
  25: // Step D: Post-Repair Independent Collision Validation or Conditional Checkpointing
  26: if outcome == COMPLETED and Cost(P_cand) < Cost(P_inc) and IndependentPathValidator(P_cand) [incurs
  t_verify] then
  27:      Increment v_traj[u] for modified agents u; P_inc <- P_cand
  28: else if outcome == INTERRUPTED and ShouldCheckpoint(C_new) and (B - t_now) > t_reserve then
  29:      InsertOrReplaceBounded(S_chk, C_new, max_capacity = K) [incurs t_save]
  30: LogIterationTelemetry(L, a*, Delta*, outcome, Cost(P_inc), actual_overheads)
  31: return P_inc, L
